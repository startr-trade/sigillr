# v0.1.0

_Released 2026-11-22._

## What shipped

### FEAT-001 — Rust workspace skeleton

sigillr has a Rust workspace with one crate per catalogued component and a pinned toolchain, so every later item has a place to land

- THE SYSTEM SHALL build and test with `cargo build --workspace` and `cargo test --workspace` on the toolchain pinned in rust-toolchain.toml
- THE SYSTEM SHALL carry a .gitattributes file with `* text=auto eol=lf`

### FEAT-002 — MIT/Apache-2.0 dual licence and community files

sigillr is published under MIT OR Apache-2.0 with the community files contributors and reporters need

- THE SYSTEM SHALL hold LICENSE-MIT and LICENSE-APACHE and declare `MIT OR Apache-2.0` in every crate manifest
- THE SYSTEM SHALL hold CONTRIBUTING.md, SECURITY.md, CODE_OF_CONDUCT.md and CONTRIBUTORS, with no email address in CONTRIBUTORS

### FEAT-003 — Brand assets: mark, lockups, icons and social preview

sigillr has a mark and lockups that follow the startr.trade family brand guide

- THE SYSTEM SHALL hold, in assets/brand/, Sigillr's own mark, light and dark lockups, favicon, app icon, apple-touch icon and social preview, with the file set, names and sizes Katalogr's assets/brand uses

### FEAT-004 — README with the light/dark lockup

The README introduces sigillr with the family lockup and points to the guide, contributing and security policy

- THE SYSTEM SHALL show the lockup in a `<picture>` element with a dark source and a light fallback, and link the user guide, CONTRIBUTING, SECURITY and both licences

### FEAT-005 — mdBook user guide

sigillr has a user guide that builds in CI and grows with each feature

- WHEN docs change on main, THE SYSTEM SHALL build the mdBook with no broken links and publish it

### FEAT-006 — CI: make ci matching GitHub Actions, with test tiers and portability guards

Every push and pull request runs the same checks locally and in CI, on all three systems, in tiers

- THE SYSTEM SHALL run fmt, clippy with -D warnings, the cross-target clippy and the tests in that order, the same steps ci.yml runs
- THE SYSTEM SHALL equal the one in every workflow
- THE SYSTEM SHALL pin every action to a full commit SHA and pass actionlint
- WHEN a pull request is opened, THE SYSTEM SHALL run fmt, clippy and tests on Linux, macOS and Windows
- WHEN a dependency manifest or the lockfile changes, nightly, and before a release, THE SYSTEM SHALL fail the supply-chain check on a known advisory, a licence outside the allow list, or a crate from an unknown source
- WHEN a release branch is pushed, THE SYSTEM SHALL run CodeQL static analysis as the job named sast

### FEAT-007 — Release workflow

A tagged commit is released only after its CI is green, with binaries and crates published

- IF CI has not succeeded on the tagged commit, THE SYSTEM SHALL stop before building or publishing anything
- WHEN a version tag's CI is green, THE SYSTEM SHALL publish the crates and attach Linux, macOS and Windows binaries to the release
- WHEN a version tag's CI is green, THE SYSTEM SHALL attach a CycloneDX software bill of materials to the release
- THE SYSTEM SHALL provide install.sh and install.ps1 that download a release archive and refuse to install it unless its SHA-256 matches the published checksum
- IF a built release artifact has a fixable high or critical vulnerability, THE SYSTEM SHALL fail the artifact-scan job and publish nothing
- WHEN a version tag's CI is green, THE SYSTEM SHALL attach a build provenance attestation for every archive

### FEAT-008 — Release 0.1.0 claiming the Sigillr name on crates.io

sigillr 0.1.0 is on crates.io and its binary answers --version and --help

- WHEN run with --version, THE SYSTEM SHALL print its name and the crate version and exit 0
- WHEN run with --help, THE SYSTEM SHALL print its usage and exit 0
- WHEN 0.1.0 is tagged, THE SYSTEM SHALL publish the sigillr crate to crates.io

### FEAT-009 — Architecture compliance review: open-source shape and CI

The open-source shape and CI milestone ends with its code checked against the architecture docs and ADRs

- WHEN every other item in the milestone is built, THE SYSTEM SHALL have its code reviewed against the ADRs, component docs and views it affects, with the result recorded on the board

### MNT-001 — Agent-neutral from the start: Sigillr speaks of agents, with Claude Code as one adapter

Sigillr's product text speaks of agents, never of one agent vendor, so contributors using any agent framework are at home

- IF README.md, CONTRIBUTING.md, a page under docs/guide or a crate source names an agent vendor outside the adapter files (CLAUDE.md, .claude/, AGENTS.md), THE SYSTEM SHALL fail its archtests
- THE SYSTEM SHALL state the agent-neutral wording rule in CONTRIBUTING.md
